# 한국형 썸 메신저: 기초 설계

상태: 대화 중인 초안. 아래의 사용자 요구와 설계 제안을 구별한다.
기록일: 2026-09-06

## 확인된 사용자 요구

- 혼자 참가하는 해커톤용 웹서비스다.
- 한국식 카톡·DM처럼 AI와 직접 썸 대화를 나눈다.
- 소개팅 후, 대화가 잘 통했던 상대와 연락처를 교환한 후 등 상황을 랜덤으로 부여한다.
- 4~5차례 정도의 짧은 티키타카를 생각하고 있다.
- 이모티콘을 쓸 수 있고, 읽지 않거나 답장을 늦추는 행동도 경험에 포함한다.
- 대화 후 점수, 잘한 점, 고칠 점을 제공한다.
- AI의 현실감과 자료에 근거한 평가를 핵심 개발 대상으로 삼는다.
- 사용자는 카톡을 어떻게 이어갈지 막막할 때 상황별 대처법을 배우고 싶어 한다.
- 서비스의 중심은 게임 형식과 직접 참여를 통한 대화 학습이다. 점수와 재미는 이 학습 경험을 구성한다.
- 막혔을 때 사용자가 선택해서 누르는 힌트 버튼을 제공한다. 힌트는 대화 방향을 안내하고, 실제 답장은 사용자가 직접 작성한다.
- 답장 지연은 가상 시간으로 표현한다. 사용자가 지연 시간을 선택하거나 상대의 답장이 늦어져도 실제로 그 시간만큼 기다리지는 않는다.
- 첫 대상은 썸 대화에 자신 없는 20~30대 성인이다.
- 시작할 때 대화 상대 성별을 선택할 수 있고, 각 성별 안에 다양한 성격을 제공한다.
- 상대 성향은 기본 랜덤이며 적극성·장난 선호를 조절할 수도 있다. 시작 전 이전 대화들을 읽으며 상대 성향을 파악할 수 있도록 한다.
- 힌트 사용은 점수를 감점하지 않고 사용 횟수만 표시한다.
- 대화 기술 점수와 상황 결과는 별도로 표시한다.
- 평가 후 아쉬웠던 메시지부터 다시 답장하고 이전 대화와 달라진 반응을 비교한다.

## 핵심 제안

일단 상황 카드 하나에서 시작해 메신저 대화를 마치고 근거가 붙은 피드백까지 볼 수 있는 작은 흐름을 만든다. 첫 검증은 화면의 기능 수보다 상대가 실제 사람처럼 일관되게 반응하는지, 피드백이 납득되는지에 집중한다.

### 사용 흐름 초안

1. 대화 상대 설정 또는 랜덤 시작
2. 관계 배경과 현재 사건을 담은 상황 카드 및 이전 대화 확인
3. 메시지·이모티콘·답장 지연을 포함한 대화
4. 대화 종료와 평가
5. 특정 메시지부터 다시 시도하고 이전 기록과 비교

특정 메시지부터 재시도하는 기능까지 사용자 동의를 받았다. 먼저 한 상황에서 대화와 평가가 끝까지 작동하는 흐름을 만들고, 그 흐름에 재시도를 연결한다.

### 화면 세 개

| 화면 | 최소 내용 |
|---|---|
| 시작 | 랜덤 상황 카드, 상대 프로필, 이전 대화 미리보기, 시작 버튼 |
| 대화 | 말풍선, 시간, 읽음 표시, 입력창, 이모티콘, 지연 행동, 선택형 힌트 버튼 |
| 복기 | 항목별 대화 기술 점수, 별도 상황 결과, 근거 말풍선, 좋은 점과 바꿔볼 점, 힌트 사용 횟수, 재시도 |

## AI의 기본 구조 제안

### 상황과 인물

무작위 항목을 아무렇게나 섞는 대신, 일관된 기본 상황을 만들고 허용된 변형을 섞는다. 예를 들어 연락처만 교환한 상황에는 이미 함께 여행했다는 기억이 생기지 않아야 한다.

대화 상대는 성별과 별개로 다음 특성을 가진다.

- 대화를 먼저 여는 적극성
- 농담 선호와 표현 방식
- 평소 연락 습관
- 현재 일정과 답장 가능한 시간
- 현재 관계에서 허용하는 친밀함

남성·여성 상대를 모두 지원하고 각 버전 안에서 여러 성향을 제공한다. 미리보기는 시나리오용으로 준비한 6~10개 배경 말풍선이다. 농담에 대한 반응, 질문 방식, 말투와 연락 습관의 단서를 담아 사용자가 상대를 파악하도록 한다.

### 대화 상대와 평가자의 역할

대화 상대는 캐릭터 설정과 대화 기록을 바탕으로 응답한다. 평가자는 종료된 기록과 평가 기준을 읽고 피드백을 작성한다. 같은 기반 모델을 두 역할로 나눠 사용하는 작은 구현부터 검토한다.

사용자가 숨겨진 상대 취향을 알아맞히지 못했다고 감점하지 않는다. 상대가 바빠서 대화가 끝난 경우에도 사용자의 대응은 좋을 수 있다.

### 시간

읽은 시각과 답장 시각을 구분한다. 사용자와 AI 모두 메시지 여러 개를 연달아 보낼 수 있으므로 말풍선 수와 대화 차례 수를 동일하게 취급하지 않는다.

답장 지연은 가상 시간으로 진행한다. 예를 들어 '30분 뒤 답장'을 선택하면 대화 속 시계가 이동한다. AI의 지연 답장도 경과 시간을 표시하며 진행한다. 짧은 연출 시간과 실제 한 판 길이는 아직 확정하지 않았다.

### 평가

기존 [자료 조사와 평가 기준](../research/ai-conversation-rubric.md)을 출발점으로 삼는다. 근거 자료, 설계자의 임시 기준, 사용자 검증 결과는 분리해서 기록한다.

학습 목표는 막막한 카톡 상황에서 대화를 풀어가는 방법을 익히는 것이다. 대화 기술 점수와 시나리오 결과를 분리해서 표시하기로 확정했다. 예를 들어 대처는 좋았으나 상대 일정 때문에 약속이 보류될 수 있다. 힌트 사용은 감점하지 않으며 횟수만 표시한다. 항목별 비중은 아직 임시 설계이고, 관찰이 부족한 항목에는 점수 대신 관찰 부족을 표시하는 방향을 제안한다.

## 개선 방향을 판단할 검증 질문

1. 짧은 답장에도 캐릭터가 자연스럽게 반응하는가?
2. 적극적인 상대와 조심스러운 상대가 서로 다르게 느껴지는가?
3. 앞서 공개한 일정과 이전 발언을 기억하는가?
4. 이모티콘·나눠 보내기·답장 지연이 실제 상황에 영향을 주는가?
5. 피드백이 실제 메시지에 연결되고, 서로 다른 좋은 표현을 인정하는가?
6. 같은 기록에 대한 평가가 일관적인가?

현재 검증은 미실행이다. 사용자에게서 재미·현실감·피드백 유용성을 각각 확인하고, 낮게 나온 항목부터 개선한다.

## 현재 결정할 사항

- 이전 대화는 준비된 배경 말풍선 6~10개로 확정했다.
- 첫 상황은 소개팅 후 첫 연락, 연락처 교환 후 말 걸기, 끊긴 대화 이어가기, 애프터 제안, 약속 취소에 대응하기의 5개다.
- 초기 AI 개발·테스트 예산 상한은 총 1만 원이다. 실제 사용 비용을 확인한 뒤 조정한다.
- 작업 관리 설정: 로컬 작업 파일, 기본 상태 이름, AGENTS.md 사용 제안

첫 작동 버전에서는 사용자 답장 5회 후 평가한다. 여러 말풍선을 한 차례에 보낼 수 있다. 점수는 대화 종료 후 공개한다. 이는 짧은 플레이를 위한 구현 기본값이며 조정 가능하다. API 키가 없는 동안은 명시적인 체험 모드로 실행하고 실제 AI 채점인 것처럼 표시하지 않는다. AI 제공자와 배포 방식은 추후 변경 가능하다.

## 인터뷰 결정 기록

- Q1 확정: 카톡이 막막할 때 어떻게 대화를 풀어갈지, 특정 상황에 어떻게 대응할지 게임·참여형 경험으로 배운다.
- Q2 확정: 필요할 때 힌트 버튼을 눌러 대화 방향을 안내받는다. 답장은 사용자가 직접 작성한다.
- Q3 확정: 답장 지연은 가상 시간으로 진행한다.
- Q4 확정: 대화 기술 점수와 시나리오 결과를 별도로 표시한다.
- 묶음 질문 1 확정: 썸 대화에 자신 없는 20~30대 성인을 첫 대상으로 삼는다.
- 묶음 질문 2 확정: 상대 성별을 선택하고, 각 성별 안에서 다양한 성격을 제공한다.
- 묶음 질문 3 확정: 대화 기술 점수와 상황 결과를 분리한다.
- 묶음 질문 4 확정: 기본 랜덤과 성향 조절을 제공하며, 이전 대화를 읽고 상대 성향을 파악하는 경험을 추가한다.
- 묶음 질문 5 확정: 힌트는 감점하지 않으며 사용 횟수만 표시한다.
- 묶음 질문 6 확정: 특정 메시지부터 재시도하고 이전 대화와 반응을 비교한다.
- 질문 진행 방식: 재시도한 선택지 UI도 사용자에게 보이지 않은 것으로 확인되었다. 이후 질문은 일반 채팅에서 여러 개씩 묶어서 제시한다. 항목별 추천을 함께 적고 명시적인 답변을 받은 내용만 확정한다.
- 마지막 묶음 질문 확정: 배경 대화 6~10개, 초기 상황 5개, 초기 AI 테스트 예산 총 1만 원 상한. 사용자 답변은 “모두 추천으로”다.
