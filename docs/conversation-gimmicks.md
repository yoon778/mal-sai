# 말사이: 이벤트와 표현 평가 설계안

정리일 2026-09-07
적용 완료: 8개 연습 상황 추가, 가상 시간에 따른 선연락, 연락 약속 수습, 근거 원칙 복기, 제한적인 표기 안내
가벼운 오타와 채팅 표현은 검사하지 않으며, 맞춤법 안내는 어이없다 표기와 회복 맥락의 나아·나으세요만 우선 지원
표기 오류 위치만 교정한 사본을 채점에 사용하고 화면의 원문은 유지
코칭 모델은 소규모 비교 후 GPT-5.4 mini로 변경, 검증 기록은 아래 참고
앞선 [유튜브 대화 강좌 조사](../research/youtube-conversation-lessons.md)를 바탕으로 사용자 제안을 정리

## 교육 중심

앞말을 받아주기, 상대가 말할 여지 만들기, 이전 소재 활용하기, 현재 반응에 맞춰 이어가거나 끝내기
모든 답장에 공감·자기 이야기·질문을 강제로 넣지 않음
이벤트는 이 행동을 연습할 기회를 만들고, 복기는 실제 사용자의 선택에 근거함

## 선톡 이벤트

번호나 인스타 계정만 교환한 직후부터 시작
사용자가 가상 시간을 넘기면 인물 성향·상황에 따라 상대가 먼저 메시지를 보낼 수 있음
실제 입력·읽기 시간은 감점하지 않음 — 게임의 가상 시간 선택과 구분

| 상황 | 이벤트 | 평가 방향 |
| --- | --- | --- |
| 연락 시점을 약속하지 않음 | 먼저 보내기 / 상대가 먼저 보내기 / 아직 연락 없음 | 누가 먼저 보냈는지만으로 감점하지 않음 |
| 사용자가 집에 도착하면 먼저 연락하기로 함 | 다음 날 상대가 먼저 안부를 물음 | 약속한 연락을 놓쳤다는 피드백, 게임 속 분위기는 소폭 하락 가능 |
| 상대가 먼저 질문하며 대화를 열어줌 | 선톡 받기 | 먼저 보낸 사람보다 사용자가 질문을 받고 이어갔는지 평가 |
| 늦어진 사정을 설명하거나 지난 이야기를 회수함 | 어색함 회복 기회 | 실제 후속 답장에 따라 회복 가능 |

‘매력’ 대신 게임 속 ‘대화 분위기’와 ‘대화 기술 평가’를 구분하는 방향 제안
캐릭터의 반응 수치는 가상의 사건 결과이며 사람 자체의 매력이나 현실 호감 확률이 아님
여성·남성 모두 같은 원칙 사용
처음부터 공개되지 않은 연락 기대·취향을 못 맞혔다고 감점하지 않음
시험 몰입을 위해 대화 중에는 상대의 말과 읽음 상태를 보여주고, 점수 변화 이유는 종료 뒤 복기에서 공개하는 방식 추천

## 맞춤법과 말투

| 구분 | 예 | 처리 제안 |
| --- | --- | --- |
| 채팅식 표현 | 머해, 웅, 그랬엉, ㅋㅋ, 띄어쓰기 생략, 온점 생략 | 교정·감점하지 않음 |
| 가벼운 실수 | 일회성 오타, 쉽게 복원되는 빠진 글자 | 원칙적으로 넘어감 |
| 명확한 표기 오류 | 어의없다 → 어이없다, 아픈 상대에게 빨리 낳아 → 빨리 나아 | 종료 뒤 해당 부분만 짧게 안내, 한 번으로 매력 감점하지 않음 |
| 뜻을 확인해야 하는 문장 | 약속 날짜·시간·부정 표현이 서로 모순됨 | 상대가 자연스럽게 확인 질문, 설명으로 복구 가능 |
| 부담을 주는 언어 행동 | 비꼼, 죄책감 유도, 답장 독촉, 거절 무시, 인격 비하 | 전후 맥락·반복·경계를 근거로 평가 |

‘심각한 맞춤법’은 공식적인 오류 등급이 아니라 제품의 표시 기준
확신이 낮은 구어체·사투리·고유명사는 교정하지 않음
긍정·부정이 불분명한 문장을 AI가 마음대로 고쳐 뜻을 바꾸지 않음
맞춤법 안내는 대화 기술 점수와 따로 표시하고, 같은 표현을 반복 감점하지 않음

아래는 영상 인용이 아닌 직접 만든 부담 표현 예시:

- 비꼼: 이제야 답장하시네 ㅋㅋ
- 죄책감 유도: 나만 너한테 진심이네
- 강요: 바빠도 1분이면 답하잖아
- 취향 비하: 그걸 왜 좋아해? 수준 낮네
- 거절 무시: 싫다는 말을 들은 뒤 반복해서 만나자고 요구

‘ㅋㅋ’나 단어 하나 자체를 문제로 판정하지 않음
서로 합의한 장난·인용·불편한 요구를 거절하는 답변은 같은 문구라도 해석이 달라질 수 있음

## 이벤트 후보

| 이벤트 | 예시 상황 | 연습할 행동 |
| --- | --- | --- |
| 상대가 먼저 연락 | 사용자가 가상 시간을 넘긴 뒤 안부 도착 | 질문을 받고 흐름 이어가기 |
| 스토리에서 대화 시작 | 가상의 카페·영화 스토리가 나타남 | 보이는 소재로 자연스럽게 말 걸기 |
| 지난 이야기 회수 | 배경에 있던 발표·시험이 끝난 날 | 상대가 말한 내용을 기억해서 연결 |
| 이야깃거리 건네기 | 상대가 제안을 직접 하지 않고 가보고 싶은 전시를 언급 | 관심 확인 후 자연스럽게 제안하기, 초대 의도 단정 금지 |
| 짧은 반응 | 몇 차례 질문 뒤 짧은 답이 옴 | 같은 질문 반복보다 주제·부담·마무리 판단 |
| 농담이 안 통함 | 장난에 상대가 당황하거나 불편함을 표현 | 해명·사과·주제 전환, 농담 강요 금지 |
| 말뜻이 엇갈림 | 한 문장이 단정·거절로 오해될 여지 | 변명보다 의도를 명료하게 설명 |
| 갑자기 바빠짐 | 대화 중 회의나 이동 예정이 알려짐 | 기다리기·다음 대화 연결·재촉하지 않기 |

첫 구현은 선톡 / 지난 이야기 회수 / 농담 후 수습 3개 추천
한 판 5차례에 핵심 이벤트 1개를 먼저 적용하고 필요할 때 작은 후속 반응을 더하는 범위 제안
무작위 사건만 발생시켜 실패시키지 않고 앞선 대화·성향·일정과 연결
특정 차례 재도전 시 같은 초기 사건을 유지해 사용자가 다른 답장을 비교할 수 있게 설계

## 최소 적용 구조

- 이벤트 조건·가상 시간·발생 여부·되돌리기는 서버에서 결정
- AI 상대는 결정된 사건과 현재 대화를 바탕으로 메시지를 작성
- 평가 AI는 공개된 단서·사용자 답장·관련 교육 원칙만 검토
- 기존 복기 카드에 해당 사건에서 좋았던 선택, 놓친 단서, 다른 답장, 후속 행동을 연결
- 맞춤법은 별도 안내 항목으로 분리하고 원문·교정 제안·이유를 제한적으로 제공

학습 효과·분위기 변화량·이벤트 빈도는 아직 검증되지 않은 제품 가설

## 적용 검증

- 자동 테스트 27개, 기존 30개 평가 사례 데이터 검증
- 새 상황 8개를 존댓말·반말로 각각 5턴 완주하고 재시도 확인
- 브라우저에서 지연 전송 중 선연락이 왔을 때 초안 보존, 복기, 같은 선연락 장면 재도전, 스토리 표시 확인
- 375 / 768 / 1440px에서 채팅·복기 가로 넘침 없음, JavaScript 오류 없음
- 맞춤법·사과·비하 신규 AI 평가 4개: 동일 최종 프롬프트에서 GPT-4.1 mini 2/4, GPT-5.4 mini 4/4
- 작은 창작 사례 집합이며 전체 품질이나 실제 학습 효과를 보장하는 수치는 아님
- 공식 품질 개선 참고: https://developers.openai.com/api/docs/guides/model-optimization

체험 모드는 실제 의미에 따른 분위기 회복·맞춤법·기술 점수를 판단하지 않음

최종 API 검증: 신규 평가 4/4 및 선연락 후 5턴 완주·수습·복기 통과
