# 말사이 토스 출시 준비

## 구현 범위

- Apps in Toss Web Framework 3.3.0, Vite 8.2.2, `.ait` 빌드 연결
- SDK의 `User.getAnonymousKey` 식별값을 서버가 토스 mTLS API로 검증
- 운영 API의 HTTPS 공개 주소와 토스 정식·QR 테스트 출처만 허용
- 사용자별 SQLite 기록, AES-256-GCM 암호화, 재접속·서버 재시작 후 복원
- 스키마 버전 1 초기화는 트랜잭션으로 처리하며 알 수 없는 상위 버전과 잘못된 암호화 키는 시작 차단
- 기록 조회·전체 삭제·AI 답장 신고, 운영자 신고 조회와 AI 중지 명령
- AI 입력·출력 안전 검사, 검사 실패 시 응답 차단, 사용자별 하루 요청 한도와 기존 누적 3달러 상한 유지
- 요청 ID·기록 버전으로 중복 전송 방지 및 응답 유실 복구, 같은 사용자 검증의 동시 요청 통합
- 1~5턴 조기 마무리와 한 문장 복습, 별도 동의를 받는 답장·평가 품질 제보

정식 서비스 배포는 아직 하지 않았습니다. 현재 생성한 시험 패키지는 연결되지 않는 `https://api.example.invalid` 주소를 사용하므로 제출용이 아닙니다.

2026-09-09 검증: 자동 테스트 66개, 평가 사례 형식 검증 30개, 토스 패키징 통과. SDK 모의 브라우저에서 안전 영역·저장소·대기 중 뒤로가기와 앱 종료·CSP 차단 확인. 320/375/768/1440px에서 가로 넘침과 JavaScript 오류 없음. 이번 점검은 유료 AI 호출 없이 진행했으며 실제 토스 기기·mTLS 검증은 남아 있음. 상세 내용은 [보안 점검 기록](toss-security-review-2026-09-09.md) 참고

## 로컬 실행

Node 24 이상에서 `npm ci`, `npm start`를 실행합니다. `.env`의 기존 API 키를 사용하며 `.data/storage.key`를 자동 생성합니다. `.data/practice.sqlite`와 이 키를 함께 보존해야 이전 기록을 읽을 수 있습니다. 이전 버전의 서버 메모리에만 존재하던 대화는 이관할 저장 파일이 없습니다.

## 운영 API

1. 토스 콘솔에서 앱 이름을 확정하고 mTLS 인증서와 개인키를 발급합니다. `mal-sai`는 현재 개발용 이름이며 사용 가능 여부를 아직 확인하지 않았습니다.
2. HTTPS 도메인과 지속 디스크가 있는 서버를 준비합니다. Dockerfile은 Node 기본 모듈만 사용하는 API 서버이며 TLS 종료 프록시 뒤에서 실행합니다. 프록시는 원래 Host를 유지하고 3000번 포트를 외부에 직접 공개하지 않습니다. API 서버에서 관찰되는 프록시의 정확한 연결 IP를 `TRUSTED_PROXY_IP`로 지정하고, 프록시는 `X-Real-IP`를 실제 클라이언트 IP로 덮어써야 합니다. 클라이언트가 보낸 값을 그대로 전달하면 안 됩니다. 다중 프록시·유동 IP 호스팅은 현재 지원하는 단일 프록시 구성과 다르므로 호스팅 구조에 맞는 별도 검토가 필요합니다.
3. `.env.toss.example`의 서버 설정을 호스팅 비밀 설정에 등록합니다. `STORAGE_KEY`는 무작위 32바이트의 64자리 hex입니다. 인증서 파일과 키는 읽기 전용으로 마운트하고 `/data`는 쓰기 가능한 영구 볼륨으로 연결합니다.
4. 서버를 한 인스턴스로 운영합니다. 현재 요청 잠금과 SQLite/예산 파일 구조는 여러 인스턴스 배포를 지원하지 않습니다.

`AI_BUDGET_USD=3`은 서버 전체 누적 한도이며 매일 자동 초기화되지 않습니다. 사용자별 기본 한도는 하루 30회·분 구간당 6회, 서버 전체 동시 작업은 3건입니다. AI 작업 시작 후 실패·차단도 횟수에 포함되지만, 캐시된 힌트·주제 조회와 잘못된 게임 입력, 완료한 요청 재전송은 포함되지 않습니다. 비용 상한 변경은 운영 예산을 정한 뒤 별도 검토합니다.

## 미니앱 빌드와 검사

로컬 `.env.toss`에는 공개 빌드 값 `VITE_API_ORIGIN`과 `TOSS_APP_NAME`을 설정합니다. API 키나 인증서를 `VITE_` 변수로 만들지 않습니다. 허용한 공개 변수 외의 `VITE_` 설정이 발견되면 빌드를 차단합니다. 운영 모드는 절대 경로의 `DATA_DIRECTORY`, 정확한 `TRUSTED_PROXY_IP`, 암호화 키·인증서·지원 모델·비용 및 요청 한도를 시작 시 검증합니다. `NODE_ENV=production`에서 로컬 식별 모드로 시작할 수 없습니다.

```sh
npm run build:toss
npm run preflight:toss
```

빌드는 로컬 `.ait` 파일 생성까지만 수행합니다. 업로드나 심사 신청은 하지 않습니다. 출시 전 검사에는 서버 환경값도 필요합니다. 도메인·앱 이름이 빌드와 일치하는지, 고객지원 이메일·정식 개인정보 안내·실기기 검증이 완료됐는지 확인합니다.

## 운영 점검

### 인증과 브라우저 보안

- 인증 검증 API 호출은 요청원 IP당 분 구간 30회, 한 서버 전체 300회까지 허용하며 초과 시 `429`와 `Retry-After` 반환
- 같은 식별키의 동시 검증은 한 요청으로 통합, 성공은 60초·거절은 5초 캐시하며 이미 검증된 사용자는 신규 검증 제한과 무관하게 캐시 사용
- 인증 요청 제한은 서버 메모리 기준이며 재시작 시 초기화됨 사용자 AI 횟수·누적 예산의 영구 보존과 구분 필요
- IP 공유망은 제한을 함께 사용할 수 있음 분산 공격·대량 HTTP 요청 방어는 운영 프록시의 연결·속도 제한도 필요
- API 응답에 HSTS·프레임 차단·콘텐츠 유형 보호, 토스 HTML에도 CSP 적용
- 토스 패키지는 자체 스크립트·스타일과 설정된 HTTPS API 통신만 허용
- 토스 화면에서만 확대 제스처 제한, 응답 대기 중에도 native 뒤로가기·홈 이벤트로 종료 선택 가능

### AI 비용 제한

- 상황 뽑기·새로고침·기록 조회·가상 시간 이동은 AI 생성 없음
- 사용자별 AI 작업은 기본 하루 30회, 실제 시계의 분 단위 구간마다 6회까지 허용하며 초과 시 생성 전에 429로 차단
- 답장·힌트·주제 도움·복기·복습이 한도를 함께 사용하며 실패한 AI 작업도 횟수 차감
- 일일 한도는 UTC 날짜 기준, 한국 시간 오전 9시 초기화하며 SQLite에 보존되어 서버 재시작·기록 삭제로 초기화되지 않음
- 이미 받은 힌트·주제 도움·완료한 복기와 최신 기준의 재평가는 저장 결과 재사용, 추가 AI 호출 없음
- 전체 동시 AI 작업은 서버 한 인스턴스에서 기본 3건까지 허용하며 안전 검사와 복기 재생성도 같은 처리 슬롯에 포함
- `AI_DAILY_REQUEST_LIMIT=30`, `AI_MINUTE_REQUEST_LIMIT=6`, `AI_MAX_CONCURRENT_REQUESTS=3`으로 조정
- `AI_BUDGET_USD=3`은 모든 사용자가 공유하는 누적 생성 예산이며 매일 자동 초기화되지 않음 모든 모델 호출·내부 재생성은 요청 전에 같은 원장에 최대 사용량을 예약

`DATA_DIRECTORY`의 `practice.sqlite`, `budget.json`을 영구 볼륨에 유지해야 한도가 보존됩니다. 재배포 때 원장을 지우거나 인스턴스별로 별도 원장을 만들면 전역 예산 보호가 유지되지 않습니다. 현재는 한 인스턴스 운영이 전제이며 서버를 늘리기 전 공통 저장소와 동시 요청 제한을 먼저 변경해야 합니다. 이 원장은 이 앱의 추정 생성 비용만 관리하며 같은 API 키를 사용하는 다른 프로그램 비용까지 차단하지는 않습니다.

```sh
npm run reports:list
npm run reports:list -- --details
npm run ai:pause
npm run ai:resume
npm run feedback:summary
```

운영 환경에서는 같은 명령에 `DATA_DIRECTORY`, `STORAGE_KEY`를 환경 변수로 제공합니다. 기본 목록은 안전 신고·품질 제보의 식별번호·이유·접수 시각을 출력합니다. `--details`는 신고된 AI 답장과 동의한 품질 제보의 공개 대화 맥락·모델 버전도 출력하므로 운영자만 사용합니다. 중지 명령은 `.data/ai-paused` 파일로 입력 검사와 출력 공개를 차단합니다.

기록·설문·신고·품질 제보는 마지막 저장 30일 후 만료하며 최대 1시간 후 정리합니다. 전체 삭제는 모든 종류의 사용자 기록을 지우고 이용 한도 우회 방지를 위해 최근 횟수만 잠시 유지합니다. 신규 비용 로그에는 대화 ID와 대화 내용을 남기지 않습니다. 이전 버전의 `.data/usage.jsonl`, `feedback.jsonl`, 실험 결과는 자동 삭제·이관하지 않으므로 로컬 실험 디렉터리를 운영 서버에 통째로 복사하지 마세요.

## 사용자 작업이 필요한 단계

- 토스 콘솔 가입·앱 이름 확정·인증서 발급
- API 호스팅 계정·도메인 연결
- 실제 운영자·고객지원 연락처와 개인정보 처리방침, 국외 처리 안내 확정
- 토스 Android/iOS에서 실제 식별키 검증, 앱 종료 후 복원, 뒤로 가기·닫기, 키보드·안전 영역, 느린 네트워크, 신고·삭제 확인
- 콘솔의 앱 아이콘·소개·스크린샷 등록과 심사 신청

실제 토스 기기와 mTLS 검증은 계정·인증서 없이는 완료할 수 없습니다. 브라우저 테스트와 패키지 빌드 통과를 토스 출시 승인으로 간주하지 않습니다. AI 응답 품질은 별도 사용자 평가가 필요하며 안전 필터가 모든 위험을 탐지한다고 보장하지 않습니다.
