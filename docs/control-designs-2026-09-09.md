# 자주 쓰는 기능을 위한 디자인 시안

요청: 초기화와 자주 사용하는 기능의 시인성을 높이고, 웹 디자인 사례를 참고한 세 가지 도안을 제작합니다. 기존에 선택한 B안의 따뜻한 분위기를 비교 기준으로 삼았습니다.

## 적용 범위

실제 연습 화면에서는 새 연습 시작을 상단 도구 모음으로 옮겼습니다. 다른 상황 뽑기·기록·힌트·주제·전송 버튼의 배경, 테두리, 크기를 강화했습니다. 기존 API와 기록 보관 동작은 유지합니다. 실제 화면의 새 연습은 이전 기록을 보존하므로 ‘전체 삭제’나 ‘초기화’로 잘못 표시하지 않습니다.

`/designs#a`, `/designs#b`, `/designs#c`는 각 디자인을 직접 비교하는 페이지입니다. 전체 테마 교체는 이 페이지에서 비교한 뒤 선택할 수 있습니다. 대화와 복기 두 화면을 제공하고, 초기화 확인·취소, 힌트와 주제 열기, 상황 변경, 예시 전송과 재시도가 동작합니다. 예시 초기화는 시안에 입력한 내용만 지웁니다. 시안은 서버 API를 호출하지 않으며 복기는 고정 예시임을 표시합니다.

| 시안 | 방향 | 자주 쓰는 기능의 배치 |
| --- | --- | --- |
| A 간결한 도구형 | 블루와 흰색, 상황·대화 두 영역 | 상단 초기화, 입력창 바로 위 도움 버튼 |
| B 대화 퀘스트 | 기존 코랄·크림 분위기, 미션과 진행 단계 | 상단 초기화, 넓은 도움 버튼, 진한 전송 버튼 |
| C 메신저 집중형 | 세이지, 넓은 채팅 영역, 접히는 상황 설명 | 상단 초기화, 입력창 아래 도구 모음, 대화 옆 복기 |

후속 선택에 따라 실제 화면에 기존 디자인과 B안의 시각적 요소를 혼합 적용했습니다. 노란 미션 카드·말풍선 장식·화면 구조를 유지하며, 코랄색 전송 버튼, 두 줄 설명과 아이콘이 있는 힌트·주제 카드, 가벼운 테두리와 그림자를 적용했습니다. 새 연습은 상단 오른쪽, 기록은 왼쪽에 두고 도움말·제보는 펼침 메뉴에 묶었습니다. 대화 화면의 상단 도구 모음은 스크롤 중에도 접근할 수 있습니다.

준비·읽기 전·힌트·대화·복기 화면을 320/375/768/1440px에서 확인했습니다. 작성 중인 답장 보존, 캐시된 힌트 재사용, 메뉴와 대화상자의 키보드 포커스, 전송·조기 복기·기록 보존도 검증했습니다. 사용자 실험에 의한 선호도 평가는 별도 필요합니다.

## 웹에서 참고한 원칙

2026-09-09 확인, 원본 제품 화면을 복제하지 않고 다음 원칙을 말사이에 적용했습니다.

- [Toss TDS](https://toss.tech/article/toss-design-system): 일관된 컴포넌트와 접근성 고려. 반복되는 주요 버튼에 같은 크기·상태·포커스 규칙을 사용합니다.
- [Duolingo 홈 화면 개편](https://blog.duolingo.com/new-duolingo-home-screen-design/): 다음 학습 행동을 분명하게 안내하고 복습을 흐름에 연결하는 방식. B안의 상황·대화·복기 단계에 참고했습니다.
- [Linear UI 개편](https://linear.app/now/behind-the-latest-design-refresh): 예측 가능한 액션 위치와 작업 중심의 시각적 우선순위. C안에서 대화를 넓게 두고 상황 설명을 접도록 했습니다.
- [GOV.UK 버튼 가이드](https://design-system.service.gov.uk/components/button/): 주요 행동을 여러 개의 강한 버튼으로 경쟁시키지 않으며, 되돌릴 수 없는 삭제의 경고 스타일을 별도로 사용합니다. 전송을 가장 강하게 강조하고 초기화는 테두리 버튼과 확인창으로 구분했습니다.

## 검증

- A/B/C의 대화·복기, 320/375/768/1440px에서 가로 넘침 없음
- 초기화 확인·취소·Escape, 전송·힌트·주제·복기·재시도 확인
- 전송한 말풍선이 보이도록 대화 영역 스크롤 확인
- 핵심 버튼 높이 44px 이상, 실제 연습 화면 주요 버튼 확인
- JavaScript 오류 및 시안의 API 요청 0건
- 토스 실기기·실제 사용자 사용성 검증은 별도 필요
